Модель обмена запросами и ответами Modbus на языке **Promela** и проверка её свойств с помощью **SPIN**. Один Master отправляет запросы трём Slave: адресная и широковещательная запись регистра, неверная CRC, неподдерживаемая функция и обращение к отсутствующему устройству. Скрипт собирает верификаторы, проверяет структуру модели и 14 LTL-свойств, сохраняет отчёт с контрпримером, если свойство нарушено.

## Запуск

### Требования

- **Python 3.9+**. Используется только стандартная библиотека; устанавливать пакеты через `pip` не требуется.
- **SPIN 6**. Поддержка оператора `X` не требуется. См. [установку SPIN](https://spinroot.com/spin/Man/README.html) и [документацию LTL](https://spinroot.com/spin/Man/ltl.html).
- **GCC** для компиляции верификаторов. В Windows можно использовать [GCC из MSYS2 UCRT64](https://www.mingw-w64.org/getting-started/msys2/).

### Настройка и первый запуск

```sh
git clone https://github.com/DafterT/modbus-promela.git
cd modbus-promela
```

Укажите пути к SPIN и GCC в [config.json](config.json). В репозитории задана конфигурация для Windows:

```json
{
  "spin": "%LOCALAPPDATA%/Programs/Spin/spin.exe",
  "cc": "C:/msys64/ucrt64/bin/gcc.exe"
}
```

Если инструменты доступны в `PATH`, достаточно `"spin": "spin"` и `"cc": "gcc"`. В путях Windows используйте `/` или экранируйте обратные слеши: `\\`. Переменные окружения в путях раскрываются при запуске, каталог GCC добавляется в `PATH` процесса.

Запустите все проверки из корня проекта:

```sh
python run.py
```

Результаты выводятся в консоль, полный отчёт сохраняется в `verification_results/run_*/report.txt`. Каждый запуск создаёт отдельную папку. Имена свойств автоматически читаются из объявлений `ltl` в [properties.pml](properties.pml).

## Модель и свойства

У каждого Slave есть два регистра с адресами `0` и `1`. Master выбирает значение `1` или `2`, получателя и один из вариантов запроса. Регистры изначально равны нулю и сохраняются между транзакциями.

| Запрос | Поведение модели |
| --- | --- |
| Адрес `1`–`3`, корректная функция `0x06` | Выбранный Slave записывает регистр и возвращает его адрес и значение. |
| Адрес `0`, корректная функция `0x06` | Все три Slave выполняют запись без ответа. |
| Адрес `4` | Получатель отсутствует; Master фиксирует тайм-аут. |
| Неверная CRC | Кадр игнорируется без записи и ответа. |
| Функция `0x03` | Функция в модели не поддерживается; адресный запрос получает исключение `1`. |
| Адрес регистра `2` | Адресный запрос получает исключение `2`. |

В запрос добавляется не более одной ошибки. CRC представлена логическим признаком, а тайм-аут — отсутствием ответа после завершения обработки всеми Slave. Одновременно выполняется одна транзакция; физическое время и побайтовая передача кадра отдельно не задаются.

| Свойство | Что проверяется |
| --- | --- |
| `p01_crc_ignored` | Неверная CRC не приводит к записи или ответу. |
| `p02_absent_slave` | Отсутствующий адрес приводит к тайм-ауту без изменения памяти. |
| `p03_broadcast_silent` | На широковещательный запрос никто не отвечает. |
| `p04_broadcast_written` | Корректную широковещательную запись выполняют все Slave. |
| `p05_addressed_write` | Корректная адресная запись выполняется и завершается нормальным ответом. |
| `p06_write_isolation` | Чужие устройства и невыбранные регистры не изменяются. |
| `p07_normal_response` | Нормальный ответ соответствует корректному запросу. |
| `p08_illegal_function` | Неподдерживаемая функция даёт исключение `1` без записи. |
| `p09_illegal_register` | Несуществующий регистр даёт исключение `2` без записи. |
| `p10_write_authorized` | Каждая запись допустима по содержимому и адресу запроса. |
| `p11_single_response` | За транзакцию отправляется не более одного ответа. |
| `p12_transaction_progress` | Начатая транзакция обязательно достигает результата. |
| `p13_completion_clean` | При завершении все Slave обработали запрос и каналы пусты. |
| `p14_invalid_broadcast` | Ошибочный широковещательный запрос не меняет память и не создаёт ответа. |

Предыдущие значения регистров, флаги записи и завершения и счётчик ответов позволяют проверять свойства текущего обмена.

## Результаты и артефакты

| Статус | Значение |
| --- | --- |
| `PASS` | Поиск завершён без нарушений в нужном режиме проверки. |
| `FAIL` | Найдено нарушение; сохранён контрпример и его воспроизведение. |
| `ERROR` | Проверка не завершена корректно: ошибка инструмента, тайм-аут или ограничение ресурсов. |

Для `structure` статус `PASS` означает отсутствие недопустимых конечных состояний; для LTL — выполнение выбранного свойства на исследованной модели. **Незавершённый поиск не считается успешной проверкой.** Коды завершения: `0` — все проверки прошли; `1` — есть `FAIL`; `2` — есть техническая ошибка. При сочетании `FAIL` и `ERROR` возвращается `2`.

При ошибке сохраняются файлы выполненных этапов. Контрпример создаётся, когда SPIN нашёл нарушение; при техническом сбое его может не быть.

### Если проверка не прошла

- **`FAIL`** — откройте лог свойства и `<свойство>_trace.log`, сопоставьте запрос, состояния процессов и формулу.
- **Ошибка запуска или компиляции** — проверьте пути в `config.json` и соответствующий файл `*.log`.
- **Превышение времени, глубины или памяти** — смотрите полный вывод верификатора. Скрипт ограничивает одну внешнюю команду 180 секундами, глубину поиска — 1 000 000 шагов.

Для воспроизведения сохранённого контрпримера перейдите в папку запуска и подставьте имя свойства:

```sh
spin -t -p -g -l -k p01_crc_ignored.trail properties.pml
```

## Отчёт по лабораторной работе

Лабораторная работа № 2 «Моделирование и верификация в среде SPIN» по предмету «Механизмы надежности и безопасности вычислительных систем».

- [PDF — для просмотра](report/main.pdf).
- [LaTeX — для редактирования](report/main.tex).
- [Сборка и структура отчёта](report/README.md).

В отчёте приведены описание системы, схемы Mermaid, разбор модели и всех 14 свойств, устройство скрипта и результаты проверки.

В прогоне 28 октября 2026 года структурная проверка и все 14 свойств подтверждены. Свойство прогресса не уложилось в лимит скрипта и было успешно проверено отдельной командой за 214 секунд. [Статистика и логи этого прогона](report/verification/README.md) сохранены вместе с отчётом; исходный итог скрипта — `PASS=14, FAIL=0, ERROR=1`.

## Устройство проекта

| Путь | Назначение |
| --- | --- |
| [modbus.pml](modbus.pml) | Модель Master и трёх Slave с комментариями. |
| [properties.pml](properties.pml) | Макросы наблюдения и 14 LTL-свойств. |
| [run.py](run.py) | Подготовка файлов, запуск инструментов и формирование отчёта. |
| [config.json](config.json) | Пути к SPIN и GCC. |
| [report/](report/) | Исходники LaTeX, схемы, листинги и готовый PDF. |
| `verification_results/` | Артефакты запусков; каталог исключён из Git. |

При запуске выполняется цепочка:

```text
spin -a properties.pml
gcc -O2 -DCOLLAPSE -DSAFETY -DNOCLAIM -o pan_safety.exe pan.c
gcc -O2 -DCOLLAPSE -o pan_ltl.exe pan.c
pan_safety.exe -m1000000 -w22 -q -b
pan_ltl.exe -a -N <имя_свойства> -m1000000 -w22 -b
```

`-DCOLLAPSE` сжимает состояния, сохраняя полный поиск; `-a` включает поиск принимающих циклов, `-N` выбирает свойство, а `-b` позволяет выявить превышение глубины. Команды и их вывод сохраняются в логах.

Последняя команда повторяется для каждого свойства. Генерация и компиляция выполняются один раз за запуск.
